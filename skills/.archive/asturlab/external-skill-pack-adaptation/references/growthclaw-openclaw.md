# GrowthClaw/OpenClaw Adaptation Notes

Session source: uploaded `growthclaw-openclaw-v1.0.zip`.

## Package shape

- OpenClaw-native, not Hermes-native.
- Installs to `~/.openclaw/skills/growthclaw/`.
- Creates global `~/.openclaw/workspace/brand/` and `workspace/campaigns/`.
- Mostly markdown skills/references plus JSON schemas and small local install/doctor/uninstall scripts.
- Optional keys: Brave, Replicate, ESPs, analytics, social scheduling.

## Useful core

- `positioning-angles/references/`: Dunford, Hormozi, Schwartz, unique mechanism, angle frameworks.
- `_vibe-system`: profile vs append-only files, Context Matrix, freshness rules, research quality signal.
- `positioning-angles` process: transformation, alternatives, unique mechanism, sophistication, 3-5 angles, starred recommendation, tests.
- `campaign-brief.schema.json`: repurpose as AsturLAB engagement/project record.
- `keyword-research` validation fragments: demand go/no-go, not SEO calendar.
- `stack-key-advisor` stance: cheapest useful setup, generalized to dev/AI/API stack spend.

## Reject/quarantine

Hard reject for Qayid default:

- OpenClaw/GrowthClaw wholesale install.
- Global `workspace/brand` storage.
- ESP/social scheduling keys.
- Replicate creative generation.
- Public posting/sending/scheduling automation.

Quarantine for future Khabeer or explicit user request:

- brand voice
- SEO content
- email sequences
- lead magnets
- newsletters
- content atomizer
- direct response copy
- creative

## Key lesson

The main risk was not executable malware. The package was largely inert. The real risk was behavioural: making Qayid act like a marketing publisher, writing shared global brand state, and creating public-action surfaces.

## Recommended port order

1. Read-only strategy references.
2. Qayid-native `positioning/offer pressure-test` skill.
3. Project-scoped memory protocol ideas.
4. Market-demand go/no-go check.
5. Stack/spend audit pattern.

Do not port content factories first.
